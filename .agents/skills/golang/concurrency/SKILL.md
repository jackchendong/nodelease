# 租约并发与生命周期

## 状态所有权

- 明确定义未获取、获取中、持有、释放中、已丢失和已释放状态及允许的转换。
- 用 mutex 或单一所有者循环保护内存状态；不要混用多套不一致的同步策略。
- 不复制含 mutex、`sync.Once`、原子字段、channel 生命周期或取消函数的 `Lease`。
- 不持锁调用 Redis。网络返回后必须验证操作针对的 token/代次仍是当前状态。

## 自动续租

- 后台续租循环必须有明确所有者、停止信号和完成信号。
- 从租约生命周期派生内部 context；调用方一次 `Acquire` 的 context 取消不应在方法成功返回后意外终止有效租约，除非 API 明确如此约定。
- 创建者负责停止 timer/ticker。重置 timer 时遵守模块 Go 版本的语义。
- 重试有上限并受剩余 TTL、context 和退出信号约束，不能无限快速重试。

## 通知与释放

- `Lost()` 的发送不能因无人读取而泄漏 goroutine；明确是否缓冲、是否关闭以及最多发送几次。
- 租约丢失只发布一次，并在发布前更新可见状态，使 `WorkerID()` 不再声称持有。
- `Release` 幂等，并能与续租、重复释放和读取并发执行。
- 释放时先阻止后续续租，协调正在进行的续租，再执行令牌保护的删除；不要产生“删除后又续租”的顺序反转。

## 测试

使用事件、fake 阻塞点或可控时钟协调测试，不用任意 `time.Sleep`。重点测试取消与成功同时发生、续租与释放交错、重复释放、无人读取丢失通知和大量并发申请。修改并发代码后运行聚焦 race 测试及 `go test -race ./...`。
