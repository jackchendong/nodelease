# 公共库设计

## API 与包

- 保持顶层包 `nodelease` 小而清晰；只有出现稳定且可独立测试的职责时才新增内部包。
- 构造函数显式接收必需依赖并完成配置校验，成功返回的实例应可立即使用。
- 接口在消费方定义且保持最小。不要为了 mock 复制 `go-redis` 的庞大接口。
- 只导出调用方真正需要的类型和方法。导出内容一旦发布就是兼容性承诺。
- 不使用 `init`、全局客户端或全局配置完成装配。

## 配置

- duration 使用 `time.Duration`，ID 使用能够表达约定范围的明确整数类型。
- 区分“未提供”和合法零值；特别注意最小 ID 为 `0`、最大 ID 为 `0` 以及默认开启的续租开关。
- 默认值必须在代码、Go doc 和中英文 README 中一致。
- 配置错误应尽早返回，且能够通过 `errors.Is(err, ErrInvalidConfig)` 判断。

## 错误

- 只有调用方需要分支处理时才提供哨兵错误，例如范围耗尽和租约丢失。
- 添加操作上下文并使用 `%w` 保留 Redis、context 和底层错误。
- 不比较错误文本，也不把具体 go-redis 错误文本变成公共契约。
- 网络结果不确定与确认的租约丢失不是同一状态；API 必须保守且文档明确。

## 兼容性审查

变更前检查：导出名称和签名、默认值、错误分类、channel 关闭语义、幂等性、Redis key 格式、令牌格式以及 README 示例。优先增量扩展和弃用，不在小版本中静默破坏已有调用方。
